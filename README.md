# 🍞 Калькулятор ХЕ

[![deploy](https://github.com/DevCorvette/bread-unit-calculator/actions/workflows/static.yml/badge.svg)](https://github.com/DevCorvette/bread-unit-calculator/actions/workflows/static.yml)

Помогает свести дозу инсулина и то, что реально окажется в тарелке.

🔗 **[Открыть калькулятор](https://devcorvette.github.io/bread-unit-calculator/)**

## Задача

Доза инсулина набирается шагами по 0.5 единицы, еда считается в хлебных единицах (ХЕ),
а соотношение между ними — сколько ХЕ покрывает одна единица инсулина — не константа:
оно разное в разное время суток и меняется день ото дня. Рабочий ориентир — вчерашний
приём пищи в это же время: там доза и количество еды известны и подошли друг другу.

Сегодня в тарелке будет другое количество еды, и вопрос не «какая доза
нужна точно», а «какая из соседних доз — 3.0, 3.5, 4.0 — подходит под уже набранное
и сколько ещё можно добавить». Поэтому ответ здесь не одно число, а таблица.

## Как пользоваться

1. **Инсулин** и **ХЕ** — вчерашние значения этого приёма пищи. Из них берётся пропорция.
2. Появляется таблица: доза и покрываемые ею ХЕ, по три шага вверх и вниз от введённой.
   Текущая строка подсвечена, стрелками таблица расширяется дальше.
3. Блюда добавляются по одному — кнопкой «+». Каждое становится чипом, сумма
   видна в заголовке «Набрано».
4. С первым добавленным блюдом появляется колонка **«Остаток»**: сколько ХЕ ещё влезает
   в каждую дозу.

Считается только по подтверждённым блюдам: пока «+» не нажата, таблица не дёргается
на каждую введённую цифру.

## Почему так сделано

Пользуемся с телефона, и ставить ради этого приложение не хотелось — обычная страница по
ссылке подходит лучше. Отсюда статический хостинг на GitHub Pages.

Задачу закрыла бы страница на HTML с десятком строк JS. Blazor WebAssembly взят, чтобы
разобраться с ним на практике.

---

Личный инструмент, а не медицинская рекомендация: пропорция берётся из собственных
наблюдений, калькулятор только масштабирует её.
